# CLAUDE.md

Portfolio site of Aditya Raikwar, PhD (postdoctoral researcher, spatial computing and applied ML).
Live at https://adirar.github.io. Read `HANDOVER.md` for current status, the backlog and open questions.

## How the repository is laid out

GitHub Pages serves the **repository root** of the `main` branch (classic "deploy from branch", not
GitHub Actions). So the root holds the *built* site, and the source lives in `site-src/`.

```
/                     built output, regenerated by `npm run deploy`. Never edit by hand.
  index.html, ai/, xr/, 404.html, _astro/, images/, robots.txt, sitemap.xml, .nojekyll
site-src/             Astro 7 source (the only place to make changes)
  src/data/*.json     ALL content: edit these for text, projects, papers, skills
  src/components/Home.astro   the whole page (editor UI + sections), server-rendered
  src/components/Icon.astro   every icon, by name (generic line icons only)
  src/layouts/Base.astro      <head>, SEO/OG tags, JSON-LD, skin init script
  src/pages/                  index (both), ai/, xr/ (same page, different default track), 404
  src/scripts/app.ts          all client interactivity (vanilla TS, no framework)
  src/styles/global.css       design tokens (two skins) and all styles
  public/                     images, favicon, robots.txt, sitemap.xml (copied as-is)
  tools/deploy.mjs            build + copy dist/ to the root
CLAUDE.md, HANDOVER.md, README.md   kept at the root by the deploy script
```

## Commands (run in `site-src/`)

- `npm ci` installs exact pinned versions (Node 22 or later).
- `npm run dev` starts a local preview at http://localhost:4321.
- `npm run build` builds to `site-src/dist/` only.
- `npm run deploy` builds and replaces the built files at the repository root. Then commit and push
  `main`; Pages updates in about a minute. Opening `index.html` from disk looks unstyled (root paths); use `npm run dev`.

Versions are pinned exactly (`astro@7.4.0`, fonts `5.3.0`). Pin new packages exactly too.

## How the page works

- **One page, three views ("tracks")**: `both` (/), `ai` (/ai/), `xr` (/xr/). `body[data-track]` drives them:
  - Track-specific text is rendered three times with classes `t-both`, `t-ai`, `t-xr`; CSS hides the other two.
  - Ordering uses CSS `order` with per-element variables `--o-both/--o-ai/--o-xr` (class `ord`), computed
    from `site.json > order` (projects) and `extras.json > skillOrder` (skills). No DOM reordering in JS.
  - The "Hiring for" switch is real links; `app.ts` intercepts them, swaps `data-track` and uses `pushState`.
- **Editor UI** (game-engine style, original design): Hierarchy, Scene/Game tabs, Inspector, bottom panel
  (Timeline, Console, Project assets), toolbar (decorative transform tools, Play/Pause/Step), status bar.
  - Selection: any element with `data-select="<projectId|root>"` (hierarchy nodes, milestones, assets)
    calls `select()`, which toggles `[data-pane-scene]` and `[data-pane-insp]` panes and the playhead.
  - Game view embeds YouTube from `youtube-nocookie.com` only after a click (project video, else the playlist).
  - Scene floor grid: 240 CSS cells that light up on hover (CSS only, hidden under 900px).
  - Timeline traces (gaze, EEG) are decorative CSS animations and are labelled as illustrative.
  - Milestones are evenly spaced: `.miles` uses `repeat(5, ...)` in CSS. Change that count if you add or remove one.
- **Sections below the editor**: Things I've built (cards), Publications, Skills and Certificates,
  Lab kit (objects drop in once via IntersectionObserver; one can be focused), Connect.
- **Skins**: `html[data-skin="dark"|"light"]`, dark by default, remembered in `localStorage` (try/catch).
  All colors are CSS variables defined for both skins at the top of `global.css`. Never hard-code a color in
  a component; add a token to both skins.
- Mobile (under 900px): Scene comes first, the Inspector is hidden until a project is selected, tools/gizmo/floor
  hidden, milestone labels hidden (years only). Check every change at 390px wide.
- Respect `prefers-reduced-motion` (already handled for traces, drop-in and hover transitions).

## Adding or changing content

- New project: add it to `src/data/projects.json`, add its id to all three arrays in `site.json > order`,
  optionally to `milestones` (then update the `.miles` column count), to any `extras.json > skills.*.projects`
  it uses (the skill bars count these), and put its image in `public/images/projects/`.
- Hard-coded counts to update by hand when content changes: "12 peer-reviewed papers, 6 featured projects"
  in the status bar (`Home.astro`), "12 peer-reviewed" in `site.json > profile`, and the Publications lead
  sentence in `Home.astro`.
- Publications come from the owner's Google Scholar BibTeX export plus his CV; keep `publications.json`
  in that format (APA-like authors, venue with pages, DOI link). His name is bolded automatically.

## Design rules

- Visual direction "Option D": warm beige palette, dark skin by default, Bricolage Grotesque (variable,
  self-hosted) for text, Atkinson Hyperlegible Mono only for data labels, regular-weight large headings,
  bold condensed titles only on project cards. Design canvas and decisions are listed in `HANDOVER.md`.
- The editor look borrows conventions shared by game engines (panels, tabs, gizmo, inspector components).
  Keep it an original design: no Unity (or other company) logos, icon sets or exact layouts. Brand marks for
  LinkedIn/GitHub/YouTube are currently generic icons with text labels.
- Touch targets at least 44px where practical, visible focus rings, text contrast 4.5:1 in both skins.
